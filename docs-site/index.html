LogVault

An encrypted archive for log files. Files are split into blocks, encrypted, and stored in a private cloud bucket. Every restore is checked against a SHA-256 fingerprint.

Overview

Log files often contain IP addresses, user names and error details that should not sit in plain text in the cloud. LogVault encrypts them before upload, so the storage provider only ever holds unreadable data. It also proves that a restored file is identical to the one that was uploaded.

FeatureImplementation
SegmentationFiles are cut into 1 MB blocks
EncryptionAES-256-GCM, random 96-bit nonce per block
StoragePrivate Cloudflare R2 bucket via boto3 (S3 API)
Backup & restoreDownload encrypted ZIP, restore online or offline
Integrity checkSHA-256 compared after decryption
HistorySQLite table with verification status

How it works

Upload

.log file→split 1 MB blocks→AES-256-GCM encrypt→R2 bucket→SQLite record

Restore & verify

fetch blocks→decrypt + authenticate→join→SHA-256 = original?→PASS / FAIL

Each file gets a folder in the bucket: files/<id>/manifest.json plus files/<id>/blocks/000000.enc, 000001.enc and so on. A block is stored as nonce (12 bytes) + ciphertext + tag (16 bytes).

Security design

ConcernApproach
KeysMaster key is read from the LOGVAULT_MASTER_KEY environment variable. Never stored in code or in the bucket. A separate key per file is derived with HKDF.
CredentialsR2 keys come from environment variables only.
Public accessThe bucket stays private. No ACLs are set and no public URL is enabled.
TamperingGCM authenticates every block. Changing one byte makes decryption fail. Block position is bound to the ciphertext, so blocks cannot be reordered.
Form safetyCSRF tokens on every POST, upload type allow-list, size limit.

The manifest holds the file name, size and hash in plain text so a backup can be understood without the app. Log contents are always encrypted.

Cloudflare R2 setup

  1. Cloudflare dashboard → R2 Object Storage → create bucket logvault-archive. Leave public access disabled.
  2. Manage R2 API Tokens → create a token with Object Read & Write limited to that bucket.
  3. Copy the Account ID, Access Key ID and Secret Access Key.
  4. Put them in .env (see below). The secret is shown only once.
STORAGE_BACKEND=r2
R2_ACCOUNT_ID=...
R2_ACCESS_KEY_ID=...
R2_SECRET_ACCESS_KEY=...
R2_BUCKET=logvault-archive
LOGVAULT_MASTER_KEY=<output of python generate_key.py>

Run the app

cp .env.example .env
docker compose up --build
# open http://localhost:8000

With STORAGE_BACKEND=local everything works offline, using a folder as a pretend bucket.

Deploy this site on Cloudflare Pages

This documentation is plain HTML in the docs-site/ folder. No build step is needed.

  1. Push the repository to GitHub.
  2. Cloudflare dashboard → Workers & Pages → Create → Pages → Connect to Git.
  3. Select the repository. Framework preset: None. Build command: leave empty. Build output directory: docs-site.
  4. Save and deploy. The site is live at https://<project>.pages.dev.

Or from the command line:

npx wrangler pages deploy docs-site --project-name logvault-docs

CDN & HTTPS

A CDN keeps copies of your static files on servers in many cities and answers each visitor from the closest one. That lowers latency and reduces load on the origin.

  • Global delivery: Cloudflare Pages serves the site from Cloudflare's worldwide edge network automatically. Nothing to configure.
  • HTTPS: every *.pages.dev site gets a free TLS certificate. A custom domain added under Custom domains gets one too.
  • Check it: run curl -I https://<project>.pages.dev and look for the cf-ray header (shows which edge city answered) and server: cloudflare.
  • Caching: repeat the request and check cf-cache-status. HIT means it came from the edge cache.

Only this static documentation goes through the CDN. Encrypted log blocks are never published; the R2 bucket is private and accessed only by the Flask app.

Cleanup

  • Delete test files from the app (each file page has a delete button) or empty the bucket in the R2 dashboard.
  • Delete the R2 bucket and revoke the API token.
  • Delete the Pages project.
  • docker compose down -v removes the local database volume.
